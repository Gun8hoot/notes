- Les ELF ont une structure specifique qui sert a les identifier
- Avant tous, definisons ce qu'est un ELF. 
	- Un ELF est format de fichier binaire utiliser pour les executable, objet paratager (.so) et les fichier de core dump.
	- La structure des ELF 32bit te 64bit sont differente mais tres similaire
	- Les ELF sont constituer de 4 grande partie :
		- Header ELF
		- Des information sur le programme ou un header de segment
		- Des sections
		- Des headers de segments optionnels

### Header ELF
---
- Est generalement au debut de l'ELF
- Il contient des information essentiel comme: 
	- son type (LSB/MSB)
	- son architecture (32/64 bits)
	- l'emplacement des autres parties dans le fichier
#### Identifier:
---
- L'identifier est composer de 16 bytes ![img](https://aleeamini.com/storage/2023/08/elf-header-identifier.png)
- 1 - 4 : magic number d'un fichier ELF qui permet d'identifier facilement le type du fichier
- 5 : **EI_CLASS byte** permet de dire le binaire a été compiler pour du 32 ou 64 bit (1 = 32 bits ; 2 = 64 bits)
- 6 : **EI_DATA bytes** permet de donnée l'ordre des bits (1 = LSB ; 2 = MSB)
- 7 : **EI_VERSION** est la version de ELF. Cepandant jusqu'a maintenant, il existe que une seul version disponible. Ce bytes est donc toujours mis a 1.
- 8 : **EI_OSABI** specifie la platforme (Application Binary Interface) de notre fichier.

| **0x00** | **System V**                                 |
| 0x01     | HP-[UX](https://en.wikipedia.org/wiki/HP-UX) |

| 0x04     | GNU Hurd                                     |

- 9 : **EI_ABIVERSION** specifie la versioné de EI_OSABI mais ce bytes n'est pas utile est toujours laisser a 0
- 10 - 16 : Bytes reserver au cas ou un jour une nouvelle option doit etre ajouter et sert egalement de padding pour arriver a 16 bytes

#### Type:
---
- 2 bytes qui permettent de specifier le type de fichier ELF (si c'est un executable, librarie partager, core dump, etc...)

| Value  | Type      | Meaning                                              |
| ------ | --------- | ---------------------------------------------------- |
| 0x00   | ET_NONE   | Unknown.                                             |
| 0x01   | ET_REL    | Relocatable file.                                    |
| 0x02   | ET_EXEC   | Executable file.                                     |
| 0x03   | ET_DYN    | Shared object.                                       |
| 0x04   | ET_CORE   | Core file. (Dump files)                              |
| 0xFE00 | ET_LOOS   | Reserved inclusive range. Operating system specific. |
| 0xFEFF | ET_HIOS   |                                                      |
| 0xFF00 | ET_LOPROC | Reserved inclusive range. Processor specific.        |
| 0xFFFF | ET_HIPROC |                                                      |
#### Machine:
---
- Les deux prochains bytes specifie quelle type d'architecture CPU est utiliser (x86-64, ARM, ou toute autre architecture)
#### Version:
---
- Les 4 prochain bytes ont le meme role que **EI_VERSION** dans l'identifier
#### Entry : 
---
- Cette partie est super importante
- Entry est sur 8bit sous 64 bit ou 4 bit sous 32 bit et indique l'addresse de l'entry point du binaire. L'entry point est la fonction ou le programme va commencer, generalement sur Linux l'entry point par defaut est `_start` qui va appeller notre fonction `main()`. L'addresse stocker dans cette partie est en LSB

![img](https://aleeamini.com/storage/2023/08/elf-header-part2-1.png)
#### PhOffset (Program Headers OFFSET):
---
- Est sur **8 bytes en 64 bits** ou **4 bytes en 32 bits**
- Il faut le voir comme un indicateur qui nous donne la position de la `Program Headers table`. Sa valeur est le nombre de bytes du debut de l'ELF
#### ShOffset (Section Headers OFFSET)
---
- Est egalement un offset sur **8 bytes/4 bytes** mais qui lui indique ou se trouve la `Section Headers table`
- Chaque element qui compose un fichier ELF peux se trouver n'importe ou dans le fichier, sauf deux: Le Program header qui se trouve toujours apres le header ELF et le Section Header qui se trouve toujours a la fin du fichier
- Le header ELF est comme une carte vers tous les autres element qui compose le fichier ELF
![img](https://aleeamini.com/storage/2023/08/elf-header-ph-sh.png)
### Flags :
---
- Les flags sont stocker sur **4 bytes**
- La valeur des different flags peuvent varier selon l'architecture processeur (ex. x86, arm, ...) qui a compiler le programme
- Les flags sont generalement mis a 0
#### EHSize (Elf Header Size) : 
---
- Ces 2 bytes nous donne la taille de notre header ELF
#### PhEntrySize (Program Headers ENTRYSIZE) :
---
- Ces 2 bytes nous donne la taille d'une entrée dans notre Program Headers Table
- Chaque entrée a la meme taille sans exception
#### PhNum (Program Header NUMber) : 
---
- Ces 2 bytes nous donne le nombre d'une entrée dans notre Program Headers Table
- Avec PhEntrySize et PhNum nous avons assez d'information afin de pouvoir avoir la taille total de notre Program Headers
$$PhEntrySize \times PhNum = totalSize$$
#### ShEntrySize (Section Header ENTRY SIZE) : 
---
- Ces 2 bytes nous donne la taille d'une entrée dans notre Section Headers Table
#### ShNum (Section Header NUMber) :
---
- Ces 2 bytes nous donne le nombre d'une entrée dans notre Section Headers Table
#### Shstrndx (Section Header STRing iNDeX) : 
---
- Deux bytes d'offset (meme si c'est appeller index ça a la meme utilité qu'un offset, ducoup pour s'implifier je l'ai appeller offset) pour aller jusqu'a la table `shstrtab`
